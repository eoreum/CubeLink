# 이오름 공식 블로그 편집·공개 가이드 V1.0

작성일: 2026-08-27  
기준 채널: `https://blog.naver.com/eoreum_story`  
기준 게시물: `아두이노 강좌 ⑤ 거리 경보 장치 만들기`

## 1. 블로그의 역할

이오름 블로그는 과거 RoboSpace 활동을 그대로 복제하는 보관함이 아니다. 오랫동안
쌓은 로봇·코딩·3D프린팅 교육 경험을 현재의 Eoreum과 CubeLink 이야기로 다시
연결하는 공식 채널이다.

모든 글은 다음 세 가지 중 하나의 가치를 가져야 한다.

1. 학생과 교사가 이해할 수 있는 교육 자료
2. 실제로 만들고 수업하며 얻은 경험 기록
3. 공개 가능한 범위의 Eoreum·CubeLink 개발 이야기

## 2. 현재 글에서 유지할 결

- 과장하지 않고 차분한 `~합니다`, `~할 수 있습니다` 문장을 사용한다.
- 첫 두 문장은 기술 설명보다 독자가 보게 될 변화나 경험을 말한다.
- 본문은 `01`, `02`, `03`처럼 3~5단계로 나눈다.
- 한 문단은 1~3문장으로 짧게 유지한다.
- 마지막에는 배운 내용을 한 문장으로 연결한다.
- 옛 글을 재구성한 경우 원 블로그, 원 제목, 원 작성 연도를 정확히 밝힌다.
- 안전과 주의사항은 홍보 문구보다 우선한다.

## 3. 글꼴과 간격

네이버 에디터의 기본 글꼴 체계를 유지해 모바일과 PC에서 일관되게 보이게 한다.
장식 글꼴을 여러 종류 섞지 않는다.

| 요소 | 권장 편집 |
|---|---|
| 제목 | 제목 기본 스타일, 한 줄 또는 최대 두 줄 |
| 첫 문장 | 본문보다 한 단계 크게, 굵게 |
| 보조 도입 | 기본 본문, 회색 또는 검정 |
| 단계 소제목 | 소제목 스타일, 굵게, `01 제목` 형식 |
| 본문 | 기본 본문 크기, 왼쪽 정렬 |
| 사진 설명 | 본문보다 한 단계 작게, 회색 |
| 출처·주의 | 작은 본문, `※`로 시작 |

간격 규칙:

- 제목과 대표 사진 사이에는 넉넉한 여백을 둔다.
- 사진과 설명은 붙이고, 다음 문단 전에는 한 줄을 비운다.
- 소제목 위는 두 줄, 아래는 한 줄 정도의 호흡을 둔다.
- 빈 줄을 과도하게 반복해 모바일 스크롤이 길어지지 않게 한다.
- 코드나 배선 정보는 일반 문단에 섞지 않고 별도 구역으로 분리한다.

## 4. 사진 기준

기준 글의 실물 사진은 진정성이 좋지만 세로 사진 한 장이 화면을 너무 길게 차지하고,
부품 이름과 동작을 설명하는 보조 이미지가 없다. 이후 글은 다음 기준을 사용한다.

- 대표 사진은 가능하면 가로 4:3 또는 16:9로 촬영한다.
- 한 글에 `완성 모습 → 과정 → 세부`의 3~6장을 기본으로 한다.
- 같은 장면의 유사 사진은 여러 장 올리지 않는다.
- 배경을 정리하고 전선·부품·학생 활동의 중심이 분명하게 보이게 한다.
- 회로 사진은 핀 번호를 공개할 필요가 있는 교육 글에만 간단한 화살표를 넣는다.
- 학생 얼굴, 학교명, 명찰, 연락처, 차량번호는 동의가 없으면 가리거나 제외한다.
- CubeLink 개발 사진은 보안 부품, PCB 세부, 시리얼 번호, 키, 내부 화면과 개인
  경로가 보이지 않는지 확대해서 확인한다.
- 모든 사진 아래에 `무엇을 보는 사진인지` 한 문장으로 설명한다.

## 5. 문법과 말투

- 공식 명칭은 `Eoreum`, `이오름`, `CubeLink`, `CubeLink Studio`로 통일한다.
- 회사의 주어는 `이오름은`, 개발 과정의 주어는 `개발팀은` 또는 생략형을 사용한다.
- 독자에게는 `해 보세요`보다 `확인할 수 있습니다`를 기본으로 하되, 실습 글에서는
  친근한 제안을 허용한다.
- `매우`, `혁신적인`, `최고의`, `완벽한` 같은 근거 없는 최상급 표현은 쓰지 않는다.
- 기능은 `개발 중`, `시험 중`, `검증 완료`, `제공 중`을 구분한다.
- 숫자와 단위는 `10 cm`, `1초`가 아니라 문서 전체에서 한 방식으로 통일한다.
  기술 글에서는 `10 cm`, `5 V`, `1초`처럼 국문 단위 관행과 가독성을 함께 본다.
- 물결표 범위는 `10~20 cm`처럼 단위를 마지막에 한 번 표기한다.
- 한 문장에 쉼표를 세 번 이상 사용하지 않는다.
- 느낌표와 이모지는 제목·본문 전체에서 합계 1~2개 이하로 제한한다.

## 6. 표준 글 구조

1. 검색 가능한 제목
2. 대표 사진
3. 독자의 경험을 말하는 첫 문장
4. 글의 목표를 설명하는 보조 문장
5. `01~04` 단계형 본문
6. 안전·검증 상태 또는 수업 팁
7. 한 문장 정리
8. 이전 기록의 출처 또는 현재 개발 상태
9. 관련 글 링크와 문의 안내
10. 5~8개의 정확한 태그

제목 예시:

- `아두이노 강좌 ⑥ 서보모터로 움직임 만들기`
- `3D프린팅 진로체험 — 아이디어가 모형이 되는 과정`
- `CubeLink 개발일지 ① 블록이 로봇의 움직임이 되기까지`

## 7. 과거 자료 재정립 원칙

예전 블로그는 삭제하지 않고 역사 자료로 보존한다. 새 글은 원문을 그대로 복사하지
않고 현재 관점에서 다시 구성한다.

분류 기준:

- **재작성:** 현재도 교육 가치가 있고 사진 사용 권한이 분명한 글
- **연결:** 원글 자체가 당시 현장 분위기를 잘 보여 주어 새 글에서 링크할 글
- **사실 확인:** 연락처, 프로그램명, 드라이버, 제품 링크, 안전 정보가 포함된 글
- **보존만:** 현재 브랜드와 맞지 않거나 설명 없이 옮기면 오해가 생길 글
- **제외:** 개인정보, 저작권 불명 이미지, 잘못된 기술 정보, 만료된 모집·가격 정보

재작성 글의 마지막 표기:

> ※ 이 글은 2018년 RoboSpace에 기록한 ‘원 제목’을 바탕으로, 현재의 교육 환경과
> 이오름의 관점에 맞게 다시 정리했습니다.

## 8. CubeLink 공개 범위

### 공개 가능한 내용

- CubeLink가 해결하려는 교육 문제와 학생 경험
- 블록 코딩, 3D 시뮬레이션, 미션 학습의 개념
- Desktop과 Tablet을 각각의 환경에 맞게 설계한다는 방향
- 공개 화면의 디자인 변화와 사용성 개선 과정
- 실제로 검증된 기능의 결과
- 교육자가 이해할 수 있는 안전 설계 원칙
- 시행착오에서 배운 일반적인 교훈

### 검토 후 공개할 내용

- 구체적인 회로와 핀 구성
- 미검증 하드웨어 시험 수치와 고장 사례
- 출시 전 버전 번호, 일정, 가격, 납품처
- 학교·학생·협력사 정보
- 다운로드 파일과 설치 링크
- 개발 중인 보드와 모듈의 세부 사양

### 공개하지 않을 내용

- 인증·프로비저닝 구조, 비밀키, 우회 가능성의 구체적인 악용 방법
- 펌웨어 내부 명령, 보안 경계와 취약점 세부
- 저장소의 비공개 경로, 개인 Drive ID, 토큰, 계정 정보
- 승인 전 회로도·PCB 생산 자료·부품 조달 조건
- 미출시 바이너리, 시험용 펌웨어, 내부 설치 파일
- 검증되지 않은 기능을 완성된 기능처럼 보이게 하는 표현

안전 문제를 숨기지는 않는다. 다만 공개 글에서는 학생 안전을 위한 원칙과 개선 방향을
설명하고, 공격에 이용될 수 있는 세부나 확정되지 않은 수치는 공개하지 않는다.

## 9. 게시 절차

1. 원자료와 사진의 권리 확인
2. 기술 사실을 CubeLink 프로젝트 기록과 대조
3. 개인정보·대외비 검사
4. 이오름 문체와 사진 규칙으로 초안 작성
5. 사용자 최종 승인
6. 네이버 블로그 게시
7. PC·모바일 화면, 링크, 오탈자 재확인
8. 게시 날짜와 URL을 콘텐츠 목록에 기록

사용자 승인 전에는 글을 공개하거나 기존 글의 공개 상태를 변경하지 않는다.
