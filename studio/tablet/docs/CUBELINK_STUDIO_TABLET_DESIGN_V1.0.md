# CubeLink Studio Tablet 설계서 V1.0

- 문서 버전: 1.0
- 작성일: 2026-08-26 (Asia/Seoul)
- 제품명: CubeLink Studio Tablet
- 회사: Eoreum (이오름)
- 상태: 신규 프로젝트 설계 및 UI 프로토타입 착수

## 1. 프로젝트 선언과 경계

CubeLink Studio Tablet은 Android 태블릿을 주 사용 환경으로 하는 터치 우선
교육 앱이다. 현재 PC용 CubeLink Studio를 축소하거나 반응형으로 개조하는
프로젝트가 아니다.

- Desktop은 `studio/web`과 `studio/electron`에 계속 유지한다.
- Tablet은 `studio/tablet`이라는 독립 패키지로 개발한다.
- 펌웨어는 기존 `firmware/`를 단일 기준으로 유지한다.
- 이번 작업에서는 Desktop 소스와 펌웨어를 수정하지 않는다.
- Tablet이 검증되기 전까지 기존 배포판, GitHub Pages, Windows 릴리스 경로에
  영향을 주지 않는다.

독립 Git 저장소를 중첩하지 않고 기존 CubeLink 모노리포 안의 독립 패키지로 둔다.
이렇게 하면 Desktop을 덮어쓰지 않으면서도 프로토콜, 문서, 테스트 기록과 변경
이력을 하나의 제품 저장소에서 추적할 수 있다.

## 2. 목표와 대상

### 목표

학생이 Android 태블릿 하나로 수업 흐름을 이해하고, CubeLink를 연결하고,
블록을 조립하고, 시뮬레이션으로 확인한 뒤 실제 로봇에서 안전하게 실행하게 한다.

V1의 성공 기준은 다음과 같다.

1. 처음 사용하는 학생도 다음 행동을 화면만 보고 이해한다.
2. 가로형 Android 태블릿에서 주요 기능이 손가락으로 편하게 동작한다.
3. USB-C OTG 연결, 권한, 펌웨어 검증, 안전 초기화 상태를 서로 구분해 보여준다.
4. 연결 손실 후 같은 장치를 제한된 정책으로 자동 탐색하고 복구한다.
5. 기존 CubeLink 명령·응답 규약과 안전 상태를 임의로 복제·분기하지 않는다.
6. 프로젝트가 기기에 자동 저장되고 내보내기/가져오기가 가능하다.

### 대상 환경

- 우선 대상: Android 11 이상 태블릿, 8~12인치, 가로 사용
- 기준 화면: 1280×800 및 1920×1200 계열
- 지원 방향: 가로 우선, 세로에서도 핵심 화면이 손상되지 않는 적응형 레이아웃
- 입력: 손가락 터치 우선, 키보드·마우스는 보조 입력
- 연결: USB-C OTG/USB Host를 통한 Arduino Nano 계열 CH340/CH341 USB-serial

정확한 최소 Android API, 지원 태블릿 목록, CH340 제품 ID 전체 목록은 실제
기기 시험 후 확정한다.

## 3. 제품 원칙

1. **한 화면, 한 가지 주행동:** 다음 행동을 하나의 강조 버튼으로 제시한다.
2. **손가락 크기:** 주요 조작 대상은 최소 48dp, 권장 56dp 이상으로 한다.
3. **상태를 숨기지 않음:** 포트 열림, 장치 검증, 안전 초기화, 실행 준비를 하나의
   ‘연결됨’으로 합치지 않는다.
4. **실기와 시뮬레이션을 구분:** 실제 장치가 준비되지 않았을 때 시뮬레이션으로
   몰래 전환하지 않는다.
5. **오프라인 우선:** 수업 핵심 기능, 글꼴, 아이콘, 프로젝트 저장은 인터넷 없이
   동작해야 한다.
6. **안전 우선:** 실행, 중지, 주차, 연결 손실 처리는 펌웨어의 안전 규약을 따른다.
7. **사실에 맞는 UI:** 아직 구현되지 않은 USB 연결이나 Blockly 실행을 성공한
   기능처럼 표시하지 않는다.

## 4. 화면 구조와 내비게이션

```text
홈
├─ 코딩
├─ 로봇 연결
├─ 시뮬레이션
├─ 수동 제어
├─ 프로젝트
└─ 설정
```

### 화면별 목적

| 화면 | 핵심 목적 | V1 주요 행동 |
|---|---|---|
| 홈 | 수업의 시작점과 진행 상황 표시 | 오늘의 미션 시작, 코딩/연결/시뮬레이션 바로가기 |
| 코딩 | Blockly 프로그램 작성 | 블록 선택, 자동 삽입, 실행 전 검증, 실행/정지 |
| 로봇 연결 | 물리 장치 연결 상태 안내 | 탐색, USB 권한 요청, 장치 확인, 초기화, 재연결 |
| 시뮬레이션 | 실행 전 디지털 확인 | 블록 실행 미리보기, 충돌·범위 피드백 |
| 수동 제어 | 교사 또는 허용된 학생의 관절별 점검 | 한 축씩 이동, 안전 범위 표시, 즉시 정지 |
| 프로젝트 | 학습 결과 저장·복원 | 새 프로젝트, 자동 저장, 복제, 내보내기/가져오기 |
| 설정 | 앱·수업 환경 관리 | 언어, 접근성, 모드, 장치 진단, 정보 |

### 내비게이션 규칙

- 폭 900px 이상: 좌측 고정 내비게이션으로 7개 화면을 모두 노출한다.
- 폭 900px 미만: 하단에 홈·코딩·연결·프로젝트와 더보기를 배치한다.
- 뒤로가기/딥링크를 위해 각 화면은 `#/route` 주소를 가진다.
- 현재 화면은 색, 배경, `aria-current`로 동시에 표시한다.
- Android 뒤로가기는 화면 기록을 우선하고 홈에서는 앱 종료 확인 정책을 적용한다.

## 5. 학생 모드와 강사 모드

### 학생 모드

- 기본 모드이며 미션 중심 홈을 표시한다.
- 핀 번호, 원시 시리얼 명령, 펌웨어 업로드 기능을 노출하지 않는다.
- 하나의 추천 행동과 짧은 그림 중심 안내를 제공한다.
- 안전 제한과 강사 설정을 바꿀 수 없다.
- 프로젝트는 학생/수업 영역에 자동 저장한다.
- 오류는 해결 행동을 포함한 학생 친화 문장으로 표시한다.

### 강사 모드

- 수업 PIN 또는 관리 정책으로 진입한다. PIN 저장 방식은 보안 설계 시 확정한다.
- 미션 선택·잠금, 학생 진행 초기화, 프로젝트 배포·회수, 장치 진단을 제공한다.
- 수동 제어와 캘리브레이션은 안전 조건 충족 시에만 활성화한다.
- 연결 로그를 볼 수 있지만, 펌웨어 보안이나 생산 장치 인증을 우회하지 않는다.
- 여러 학생이 사용하는 공용 태블릿의 데이터 삭제와 내보내기를 제공한다.

V1에서는 학생 모드를 완성 우선으로 하고, 강사 모드는 수업 설정과 진단의 최소
범위만 구현한다.

## 6. 반응형 해상도 전략

픽셀 크기별 별도 화면을 만들지 않고 사용 가능한 폭과 입력 밀도에 따라 구성요소가
재배치되는 방식으로 설계한다.

| 구간 | 예상 사용 | 레이아웃 |
|---|---|---|
| 900px 이상 | 10~12인치 가로 | 좌측 내비게이션 + 넓은 콘텐츠, 카드 3열 |
| 651~899px | 8~10인치/분할 화면 | 하단 내비게이션, 콘텐츠 2열 또는 축소 3열 |
| 320~650px | 세로/좁은 분할 화면 | 하단 내비게이션, 카드 1열, Blockly 카테고리 상단 |

- `env(safe-area-inset-*)`로 시스템 내비게이션/컷아웃 영역을 피한다.
- 콘텐츠 최대 폭을 제한해 큰 화면에서 시선 이동이 지나치게 길어지지 않게 한다.
- 글자 크기는 `clamp()`를 사용하되 시스템 글자 확대에서 잘리지 않게 시험한다.
- 색만으로 상태를 구분하지 않고 아이콘, 문구, 모양을 함께 사용한다.
- 가로 1280×800, 1920×1200, 세로 800×1280, 200% 글자 확대를 필수 시각
  회귀 시험 대상으로 둔다.

## 7. 기술 구조와 선택 이유

### 선택: Vite + TypeScript + Capacitor Android

```text
Tablet UI / Blockly / Missions / Project Store
                    │
       CubeLink protocol & safety state machine
                    │
            CubeLinkTransport interface
                    │
     Android USB Host + CH340 serial plugin
```

선택 이유:

- 기존 Desktop 웹/Blockly 자산은 HTML/CSS/JavaScript이므로 웹 런타임에서 가장
  적은 변환으로 재사용할 수 있다.
- Capacitor는 UI를 WebView에 두고 USB처럼 Android 전용 기능만 네이티브
  플러그인으로 구현할 수 있다.
- TypeScript 인터페이스로 전송, 프로토콜, 저장 경계를 명확히 나누어 브라우저
  모의 시험과 Android 실제 장치 시험을 같은 상위 코드에 적용할 수 있다.
- Tablet은 자체 `package.json`, 빌드 출력, 앱 ID를 가지므로 Desktop 패키징과
  충돌하지 않는다.

React 같은 대형 UI 프레임워크는 첫 골격에 추가하지 않았다. 현재 화면 전환과
상태 규모에는 작은 TypeScript 모듈이 충분하며, Blockly 자체가 이미 큰 런타임이다.
상태 복잡도가 실제로 커질 때 프레임워크 도입을 별도 결정한다.

## 8. USB-C OTG와 CH340 연결 전략

### 전제와 확인 사항

- 대상 태블릿이 USB Host/OTG를 지원해야 한다.
- Arduino Nano의 흔한 CH340 VID/PID는 후보 탐색 신호일 뿐 CubeLink 인증이 아니다.
- Android에는 Windows CH340 드라이버 설치 방식을 사용하지 않는다. 앱 내부 USB
  Host API와 CH340 USB-serial 구현이 필요하다.
- USB 데이터 연결과 4개 서보의 안정적인 전원 공급은 별개 문제다. 태블릿이
  서보 전원을 안정적으로 공급한다고 가정하지 않으며, 기존 분리 전원/공통 접지
  안전 결정을 유지한다.

### 연결 상태 기계

```text
미연결
 → 장치 발견
 → USB 접근 권한 요청
 → 포트 열기(115200, 8N1)
 → CubeLink 펌웨어 응답 검증
 → 안전 상태 확인/초기화
 → 실행 준비
 → 연결 손실
 → 제한 재탐색
 → 재검증/재초기화
 → 실행 준비 또는 사용자 조치 필요
```

포트가 열렸다는 이유만으로 `실행 준비`가 되지 않는다. 현재 Desktop 규약과 같이
펌웨어 식별, 지원 버전/포즈 프로필/필수 기능(`CUR4` 포함), `INIT_OK` 등의 상태를
검증해야 한다. 연결 손실 시 모든 실행 UI를 즉시 잠그고 실제 상태를 알린다.

### 자동 장치 탐색

1. 앱 시작과 USB attach 이벤트에서 장치를 열거한다.
2. 알려진 USB VID/PID는 후보 우선순위에만 사용한다.
3. 후보가 하나면 권한 요청 후 프로토콜 핸드셰이크를 시도한다.
4. 후보가 여러 개면 제품명/식별 정보를 보여주고 강사 또는 사용자가 선택한다.
5. CubeLink 응답을 확인하지 못한 일반 Nano/Uno는 실행 대상으로 승인하지 않는다.
6. 마지막 장치 식별자는 편의를 위해 저장할 수 있지만 인증 수단으로 사용하지 않는다.

### 자동 재연결

- USB detach, 읽기 오류, 쓰기 오류, heartbeat 중단을 서로 구분해 기록한다.
- 실행 중 손실은 즉시 실패 상태로 전환하고 자동 재실행하지 않는다.
- 1초, 2초, 4초, 8초 간격의 제한된 backoff로 동일 장치를 다시 찾는다.
- 재연결 때마다 포트 열기부터 펌웨어 검증과 안전 초기화를 모두 다시 수행한다.
- 복구 요구 응답이 오면 학생에게 자동 동작을 시키지 않고 강사/물리 확인 흐름으로
  보낸다.
- 일정 시간 이후에는 자동 시도를 멈추고 케이블·전원 확인 행동을 표시한다.

### 보안 경계

USB VID/PID, CH340 존재, 인사 문자열만으로 정품 인증을 주장하지 않는다. 현재
Nano 기반 개발 장치의 강한 인증 한계와 향후 전용 CubeLink Core/프로비저닝 설계는
기존 제품 결정대로 별도 과제다.

## 9. Blockly 태블릿 UX

기존 Desktop Blockly의 블록 정의와 생성 코드는 가능한 한 공유하되 화면과 조작은
Tablet 전용으로 구성한다.

- 카테고리는 좌측 또는 좁은 화면 상단에 큰 터치 버튼으로 표시한다.
- 카테고리 선택 후 블록 목록을 큰 카드/서랍으로 열어 미리보기와 짧은 설명을 준다.
- 블록 탭은 선택 위치 또는 권장 위치에 자동 삽입한다.
- 드래그도 지원하되 자동 삽입, 위/아래 이동, 복제, 삭제 버튼을 함께 제공한다.
- 값 입력에는 화면 키보드에 맞는 큰 필드, 증감 버튼, 안전 범위 설명을 사용한다.
- 긴 누르기에만 중요한 기능을 숨기지 않는다.
- 실행 전 빈 값, 연결되지 않은 블록, 안전 범위를 화면에서 표시한다.
- 실행 중인 블록을 강조하고 오류/전류 fault 발생 시 해당 블록으로 이동한다.
- 실행/정지 버튼은 항상 접근 가능하며 물리 실행과 시뮬레이션을 명확히 구분한다.
- 손가락 스크롤과 블록 드래그 충돌, 핀치 줌, 휴지통 오작동을 실제 태블릿에서
  별도 시험한다.

공유 후보는 블록 정의, 툴박스 데이터, XML 직렬화, 코드 생성, CubeLink 명령
변환이다. 공유하지 않을 것은 Desktop 레이아웃, 마우스 중심 단축키, Electron COM
선택 UI다.

## 10. 저장 구조

### 로컬 우선

- 프로젝트 본문: IndexedDB
- 앱 설정과 마지막 화면 같은 작은 값: Preferences 계층
- 내보내기/가져오기: 버전이 있는 JSON 파일
- 민감한 강사 자격 정보: 평문 프로젝트 데이터와 분리, 필요 시 Android Keystore

```json
{
  "id": "uuid",
  "schemaVersion": 1,
  "name": "로봇팔 기초 5",
  "workspaceXml": "<xml>...</xml>",
  "missionId": "arm-basic-05",
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "deviceProfile": "ARM"
}
```

- 편집 후 debounce 자동 저장과 화면 이탈 시 즉시 저장을 함께 사용한다.
- 손상 방지를 위해 새 레코드 검증 후 기존 레코드를 교체한다.
- 스키마 버전을 반드시 저장하고 마이그레이션 실패 시 원본을 보존한다.
- 클라우드/강사 배포는 로컬 형식을 기반으로 나중에 추가하며 V1을 막지 않는다.

## 14. 현재 프로토타입에서 동작하는 것

- 해시 기반으로 홈, 코딩, 로봇 연결 및 나머지 구조 화면으로 이동한다.
- 900px 이상에서는 좌측 내비게이션, 미만에서는 하단 내비게이션으로 바뀐다.
- 좁은 화면의 더보기 시트에서 시뮬레이션·수동 제어·설정으로 이동한다.
- 홈의 미션/바로가기 카드로 코딩과 연결 화면에 진입한다.
- 코딩 화면은 실제 Blockly 10.4.3 작업공간을 생성하고 터치 카드로 블록을 자동
  삽입한다.
- 블록의 드래그·연결·값 변경·확대/축소·휴지통이 동작한다.
- 프로젝트는 버전이 있는 XML로 IndexedDB에 자동 저장되고 새로고침 후 복원된다.
- 프로젝트 화면에서 여러 프로젝트를 만들고 현재 프로젝트를 전환할 수 있다.
- 연결 화면은 실제 구현 범위와 향후 USB 상태 단계를 사실대로 보여준다.
- 미션 화면에서 `로봇팔과 인사하기`, `물건 옮기기`, `거리 센서 경비원`을 선택하고
  목표·블록·연습 순서를 확인한 뒤 시뮬레이션 또는 코딩으로 이동한다.
- 각 미션은 `missionId`가 지정된 독립 프로젝트에 저장된다. 첫 진입 때 미션별 시작
  블록을 만들고 이후에는 연습을 이어서 열며, `미션 처음부터`를 두 번 눌러야 시작
  상태로 복원된다.
- 빠른 블록 카드는 현재 미션에 필요한 종류만 노출한다. 미션 1은 회전판 60° 이동
  앞에 삭제할 수 없는 `▶ 시작하기` 블록을 연결한 상태로 제공하며, 학생이 기다리기와
  집게 블록을 직접 추가한다. 저장된 기존 작업에 시작 블록이 없으면 첫 실행 체인의
  위에 자동 연결해 학생 작업을 보존한다.
- 빠른 블록을 누르면 새 블록을 작업공간에 흩어 놓지 않고 하나뿐인 `시작하기`
  실행 체인의 끝에 자동 연결한다. 코딩 화면 상단에는 현재 미션의 목표와 성공 순서를
  계속 표시해 학생이 별도 화면으로 돌아가지 않고도 다음 블록을 판단할 수 있다.
- 학생 이름은 계정 기능이 실제로 연결되기 전까지 예시 인명 대신 중립적인 안내와
  `학` 배지를 사용한다.
- 시뮬레이션에서 회전판·아래팔·위팔 각도와 집게 상태를 직접 바꾸고 물건 옮기기
  자동 시연을 실행하거나 처음 자세로 되돌린다.
- Desktop Studio의 `base`, `lower`, `upper`, `grip01`, `grip02` GLB 원본과 동일한
  파일을 Android 앱에 포함하며 Desktop의 관절 계층·좌표·서보 축을 공유한다.
- 3D 시점의 터치 회전, 확대/축소, 카메라 복귀가 동작한다.
- 수동 시뮬레이션과 블록 실행 전 검사는 펌웨어 v1.4.2 개발기와 같은 관절 범위
  (PIN 6 10~170°, PIN 9 30~170°, PIN 10 10~160°)를 사용한다. 범위를 벗어난
  명령은 실행하지 않고 관절·핀·요청 각도·허용 범위를 안내한다.
- 보관 자세는 공통 프로필 `PARK_90_30_160_90`에 맞춰 PIN 6=90, PIN 9=30,
  PIN 10=160, PIN 11=90으로 시각화한다.
- 코딩 화면의 `◇ 3D로 실행`은 시작 블록 아래 연결 체인만 실행 계획으로 변환한다.
  관절, 집게, 기다리기, 반복, 거리 조건, 보관 자세를 순서대로 재생하고 연결되지
  않은 블록이나 미지원 블록은 학생에게 경고한다.
- 미션 판정은 정적 블록 존재 여부만 보지 않고 3D에서 끝까지 실행된 명령 순서를
  검사한다. 실패 시 부족한 단계를 안내하고 성공 시 완료 기록·미션 체크·홈 진행률을
  갱신한다. 미션 미리보기용 자동 시연과 학생 프로그램 실행 계획은 분리한다.

아직 블록과 시뮬레이션의 실시간 연동, 충돌/가동 범위 판정, Desktop 전체 블록 세트
호환, 프로젝트 파일 내보내기/가져오기, USB 장치 탐색, CubeLink 인증, 펌웨어
초기화, 로봇 실행은 동작하지 않는다.
